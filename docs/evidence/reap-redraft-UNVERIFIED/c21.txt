Fourth paste — js_sys call sequence, serde schema, headless profile:
`binding/calls.txt` (the exact js_sys sequence, no hidden copies):
```
let arr = js_sys::Uint8Array::new(&input);          // view, no copy
let len = arr.length() as usize;
let mut total = 0f32; let mut n = 0usize; let mut scratch = [0u8; 65536];
let mut off = 0;
while off < len {
    let end = min(off + 65536, len);
    arr.subarray(off as u32, end as u32).copy_to(&mut scratch[..end-off]);
    // copy_to into the REUSED 64 KB scratch: the single allowed allocation.
    let (s, c) = score_chunk(&scratch[..end-off]);  // borrows scratch, no Vec
    total += s; n += c; off = end;
}
return JsValue::from_serde(&Out { score: total, n }).unwrap();
// view lifetime: `arr` borrows the JS ArrayBuffer for the call duration only.
// NEVER stash `arr` or any subarray in a static; re-acquire per call.
// the old &[u8] signature goes away (breaking change, major-version noted).
```

`numeric/order-proof.txt` (why input-order accumulation is bit-exact):
```
whole-input path: score_all folds bytes 0..N in order (single pass, f32 acc).
chunked path: folds chunk 0, then chunk 1, ... in input order into the SAME
  f32 accumulator (NOT per-chunk subtotals combined in a tree — tree order
  changes rounding and breaks bit-exactness; the test would catch it).
proof obligation in the answer: state the accumulation order in one sentence
  and show the accumulator is shared across chunks (code or it didn't happen).
counter-case documented: if a future change parallelizes chunks, bit-exactness
  is VOID and the test name must change to TestChunkedCloseWhole (tolerance).
