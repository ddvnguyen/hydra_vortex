# Issue #716 — Sender-side KV Restore Trace

## Context
Engine logs `state_seq_set_data: error loading state: unexpectedly reached end of buffer`
~13ms after STATE_PUT starts, on every save→restore cycle. The engine reader receives
EOF cleanly — the sender stopped writing (or sent a short length header).

## Root Cause

`SendRequestAsync` (RpcClient.cs:439-461):
```csharp
var header = Protocol.CreateRequestHeader(
    op, (ushort)keyBytes.Length, (ulong)payload.Length, (ushort)traceBytes.Length);
// ...
await _stream.WriteAsync(headerBuf, ct);     // ← header declares payload.Length
// ... key, trace writes ...
if (payload.Length > 0)
    await _stream.WriteAsync(payload, ct);   // ← can SHORT-WRITE on Linux
await _stream.FlushAsync(ct);
```

**`NetworkStream.WriteAsync(ReadOnlyMemory<byte>, CancellationToken)` does NOT
guarantee writing all requested bytes.** On Linux with large buffers (240-650 MB KV),
the kernel's `send()` returns the number of bytes actually enqueued to the send buffer.
When the send buffer is full (congestion, peer not consuming), `send()` returns fewer
bytes than requested — a **short write**. .NET's `NetworkStream.WriteAsync` does NOT
loop internally to complete the write.

Result: header declares `payload.Length` bytes, but fewer bytes are actually sent.
Engine reads `header.PayloadLen` bytes → hits end-of buffer → "unexpectedly reached
end of buffer".

The same bug exists in `SendAndReceiveStreamBodyAsync` (line 380) for Store stream writes.

## Affected Code Paths

| Path | File:Line | Short-write risk |
|------|-----------|-----------------|
| `SendRequestAsync` payload write | RpcClient.cs:458 | **YES** — StatePut KV blob |
| `SendAndReceiveStreamBodyAsync` body write | RpcClient.cs:380 | **YES** — Store stream body |
| `EngineMergedDecodeAsync` KV write | RpcClient.cs:984 | **YES** — merged decode KV |
| `EngineMergedDecodeStreamKvAsync` KV write | RpcClient.cs:1233 | **YES** — streamed KV |
| `SendRequestAsync` header/key/trace writes | RpcClient.cs:452-456 | NO — tiny buffers |

## Fix Plan

1. Add `WriteExactlyAsync(Stream, ReadOnlyMemory<byte>, CancellationToken)` helper
   that loops until all bytes are written (handles short writes).
2. Replace bare `_stream.WriteAsync(payload)` calls with `WriteExactlyAsync`.
3. Add byte-count verification in `SendRequestAsync`: track declared vs written,
   log ERR + increment metrics counter `RestoreStreamShortWrites` on mismatch.
4. Fail the RPC on byte-count mismatch (return error status, not Ok).
